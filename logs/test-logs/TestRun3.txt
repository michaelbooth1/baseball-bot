   The combination of confirmation_ticks=3 + min_entry_ask=0.55 +

2. VOLUME IS THE NEW PROBLEM
   TR3 produced only 2 bets despite tracking 5 games. The strict filters
   correctly identified 4 of 5 games as low-scoring (final totals: 1, 3, 2, 3)
   and fired only on the one genuinely high-scoring game (final total: 9).
   However, on that game, the inning_dedup_gap=3 prevented 2 additional
   valid bets. Volume is now the binding constraint, not precision.

3. inning_dedup_gap=3 IS TOO CONSERVATIVE
   The rationale was to prevent correlated risk from betting the same game
   twice. But analysis shows: on a game like CIN@MIA where the market is
   consistently underpricing the over (9 consecutive FADE_UNDER events),
   betting multiple times is precisely what we WANT to do. The game state
   after each scoring event is genuinely new information.
   Evidence: both forgone bets at inn5 and inn6 were structurally valid
   (high ask: 0.65, 0.68; game clearly trending toward high total; final=9).

   Proposed fix: reduce to inning_dedup_gap=2.

4. THE 8.5 LINE IS HARD TO BET ON CIN@MIA-TYPE GAMES
   Even with MIA dominating, the 8.5 ask stayed at 0.51-0.52 through innings
   4-6. min_entry_ask=0.55 correctly blocked these — the market was pricing
   8.5 correctly (game was 0-4, 1-4, 1-5 — total only 4-6, still far from 8.5).
   The 8.5 bet only became viable at inn=7 when total=7 and ask=0.69.
   This is expected behavior. For high-line bets, we naturally require more
   game state evidence before the market moves the ask above 0.55.

5. MONITOR RUNTIME COVERAGE
   COL@SD started at 01:25 UTC (evening Pacific time) and ended in the 12th
   inning at 10 runs total — an ideal betting game that was missed because
   the monitor wasn't running overnight. If we want to capture these games,
   we need to ensure the monitor runs continuously, especially for West Coast
   games which end late.

6. SMALL SAMPLE — INTERPRET WITH CAUTION
   25 total settled bets is well below the minimum for statistical confidence.
   At this sample size, a 60% win rate is statistically indistinguishable from

   - TR3 filters correctly identified the high-scoring game
   - No structural false positives in TR2 or TR3
   We need 50-100 more settled bets before drawing firm ROI conclusions.

--------------------------------------------
TEST RUN 4 CHANGES
--------------------------------------------

CHANGE 1: REDUCE inning_dedup_gap FROM 3 TO 2
  Problem: A gap of 3 is preventing valid follow-on bets on high-scoring
    games. On CIN@MIA, innings 5 and 6 both had valid signals that would
    have won, blocked by the 3-inning requirement.
  Fix: Change DEFAULT_INNING_DEDUP_GAP = 2. This allows re-entry after 2
    innings instead of 3. The 60-second same-event dedup still prevents
    duplicate bets on the same scoring play.
  Expected effect: On a 9-inning game where we bet at inning 4, we can
    now re-enter at inning 6 (gap=2) instead of inning 7 (gap=3).
    Adds roughly 1 extra bet per high-scoring game. For CIN@MIA type games
    this would have added +$53.85 profit (5T bet at ask=0.65).
  Risk: Slight increase in correlated exposure. Mitigated by the fact that
    each new signal represents genuinely new game state.

CHANGE 2: ADD SEPARATE PER-LINE inning_dedup TRACKING
  Problem: The current inning_dedup tracks the LAST BET on any line per
    game. So if we bet 7.5 at inn=4, neither 7.5 nor 8.5 can re-enter
    until inn=7 (gap=3). But 8.5 at inn=4 would be on a different
    line with different risk profile.
  Fix: Track last_bet_inning per (game_pk, line) separately, not just
    per game_pk. This allows the 7.5 line to have its own dedup window
    independent of the 8.5 line.
  Expected effect: More granular dedup. On CIN@MIA, if 7.5 bets at inn=4
    and 8.5 never bets (ask<0.55 early), 8.5 can fire independently at
    inn=7 without the 7.5's dedup clock affecting it.
  Note: The 60s same-event dedup still applies per game_pk, so two lines
    firing at exactly the same scoring event still chooses the highest edge.

CHANGE 3: NO NEW MAJOR FILTER CHANGES
  The TR3 filters are working correctly. The remaining TR3 filters should
  be kept unchanged for TR4 to isolate the impact of Changes 1 and 2:
    - min_entry_ask = 0.55    (keep — correctly blocks thin books)
    - min_current_total = 4   (keep — correctly blocks pitcher's duels)
    - runs_pace_filter        (keep — correctly blocks stalled games)
    - min_inning_high_line=5  (keep — prevents premature high-line bets)
    - confirmation_ticks = 3  (keep — successfully prevents noise spikes)
