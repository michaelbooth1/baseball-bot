Root cause: The monitor was still running at the final tick (status=Live),
meaning it hadn't seen a Final status. When the session file was written at
04:58 UTC, the game was 1 out away from ending but not yet Final.

The is_final() inning < 8 guard (added to fix the COL@SD glitch) is working
correctly — this is simply a monitoring window issue where the process wrote
its session file 1-2 minutes before the game ended.

Fix needed: When the paper trader shuts down (KeyboardInterrupt or end of
process), re-check all unsettled bets against any available final data before
writing the last session file. Alternatively, add a brief grace period loop
at shutdown: wait up to 5 minutes for any in-progress 9th-inning games to
resolve before finalizing the session.

This is a bookkeeping issue, not a model issue. The bet was correct and won.
