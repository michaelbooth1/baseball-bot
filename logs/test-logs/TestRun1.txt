--------------------------------------------
PATTERN FINDINGS ACROSS ALL 3 LOSSES
--------------------------------------------

1. SINGLE-TICK SPIKES — All 3 losses were triggered by 1-2 tick ask spikes that
   reverted within 5-15 seconds. Real scoring events produce sustained elevation
   (the market stays elevated as confirmed by wins data). False positives collapse
   back to baseline almost immediately.

2. LOW ENTRY ASK = NOISE-PRONE — All 3 losses had entry asks of 0.32, 0.42, 0.43.
   All 7 wins had entry asks between 0.28 and 0.89 (and the 0.28 was a special case).
   When the market prices the over cheaply (<0.50), the order book is thin on the
   ask side, so single random orders create large but meaningless ask spikes.

3. BID DIP FALSE JUMP (SEA@TEX) — The mid-based jump detector fired when a bid
   dipped then recovered, creating an artificial +0.07 mid movement with no
   corresponding ask change. For buy-over logic we should track ask changes,
   not mid changes.

4. "End" INNING STATE (STL@WSH, bet #4) — Placed at inning_state="End", outs=3.
   This means the inning had just finished and no more scoring was possible in
   that half. We got lucky (game ended 6-9=15 runs), but this inference was
   structurally unsound. Should be excluded.

5. CORRELATED MULTI-LINE BETS — CHC@TB fired two bets at the exact same
   millisecond (lines 7.5 and 8.5). LAD@TOR fired bets 6 and 8 on the same game.
   This doubles risk and doubles reward on the same underlying event. In this run
   both lines won (CHC@TB, LAD@TOR). For a cleaner test, pick the single
   highest-edge line per game per scoring event.

TEST RUN 2 CHANGES
--------------------------------------------

CHANGE 1: SUSTAINED JUMP CONFIRMATION (fixes losses 1 and 3)
  Problem: Single-tick ask spikes trigger the bet even if they revert immediately.
  Fix: Require that the ask price has been elevated above baseline by >= jump_threshold
       for at least 3 consecutive ticks before placing a bet. Add a "pending signal"
       state — when a jump is first detected, wait for 2 more ticks of confirmation
       before executing. If the ask drops back during confirmation, cancel the signal.
  Expected effect: Eliminates almost all false positives. Real scoring events stay
       elevated for 20-60+ ticks. Noise spikes revert within 1-3 ticks.

CHANGE 2: TRACK ASK CHANGE, NOT MID CHANGE (fixes loss 2)
  Problem: The jump_magnitude uses mid = (bid+ask)/2. When bid dips, mid drops,
       then when bid recovers, mid jumps — generating a false positive signal with
       no actual change in ask.
  Fix: Track ask_history separately. Compute jump as: ask[-1] - ask[-6]. Only
       trigger when ask itself has risen, not mid recovered from bid noise.
  Expected effect: Eliminates bid-dip false positives. Ask is what we pay; it
       rising means someone is buying aggressively (informed front-running).

CHANGE 3: MINIMUM ENTRY ASK FILTER (context filter)
  Problem: When ask < 0.45, the market is already pricing the game as likely
       under the line. Order books are thin; random orders create large spikes.
  Fix: Add minimum_entry_ask = 0.45 param. Skip any signal where current ask
       is below this threshold.
  Expected effect: Filters out KC@CLE and ATL@LAA losses. May miss some valid
       low-probability edges but dramatically reduces noise-triggered bets.
  Note: The STL@WSH win (ask=0.28) was lucky, not structural — it's acceptable
       to sacrifice those.

CHANGE 4: EXCLUDE "End" AND "Middle" INNING STATES
  Problem: "End" state (outs=3) means the inning just ended. No scoring is
       possible. "Middle" is between top and bottom halves — also no active play.
  Fix: Skip bet if inning_state in {"End", "Middle"}. The batting team is
       undefined and no immediate scoring event is possible.
  Expected effect: Prevents structurally invalid inferences. STL@WSH (End4) won
       by luck but the inference was wrong.

CHANGE 5: ONE BET PER GAME PER SCORING EVENT
  Problem: Multiple lines (7.5 and 8.5) fire simultaneously on the same game/event
       creating correlated double-risk.
  Fix: Track last_bet_game_ts per game_pk. If a bet was placed on any line for
       this game in the last 60 seconds, only place a new bet if the current
       signal's edge is higher than the previous bet's edge. Otherwise skip.
  Expected effect: Cleaner per-event sizing. Limits max exposure per scoring
       event to one bet regardless of how many lines meet threshold.
