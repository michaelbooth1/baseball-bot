CRITICAL FINDING #1 (BUG): STAGE-2 NOT APPLIED TO FINAL FV
--------------------------------------------

** BUG CONFIRMED AND FIXED IN TR7 **

During TR6 analysis, verification showed the Stage-2 run-environment adjustment was
computed and logged, but NOT incorporated into the final fair_value used for edge
calculation. Stage-3 (team offense) was applied to the raw Stage-1 FV instead of
the Stage-1+Stage-2 combined FV.

Root cause: In _process_tick(), the sequence was:
  1. base_fv = best_fv          # Stage-1 FV stored
  2. best_fv = s2_adjusted       # Stage-2 applied → best_fv now = S1+S2
  3. adjusted_fv = offense_model.adjust_fv(base_fv=base_fv, ...)  # BUG: uses S1, not S1+S2
  4. best_fv = adjusted_fv       # Final FV = S1+S3, Stage-2 is DISCARDED

Fix applied (TR7): Changed line 611 from base_fv=base_fv to base_fv=best_fv.
This means Stage-3 now correctly applies its logit delta on top of Stage-1+Stage-2.

IMPACT ANALYSIS (confirmed with historical data):
  bet             | S2 delta | reported edge | true edge | diff
  HOU@SEA 7.5    | -0.258   | 0.340         | 0.324     | -0.016
  COL@SD 8.5     | -0.241   | 0.215         | 0.176     | -0.039  ← largest discrepancy
  NYY@TB 7.5(TR5)| -0.085   | 0.199         | 0.184     | -0.016
  COL@SD 7.5     | -0.033   | 0.224         | (small diff)

Key finding: NO bet decisions would have changed retroactively. The discrepancies
are 0.004–0.039, and all bets still had edge well above threshold (0.10/0.13).
However, the fix is critical going forward because:
  (a) Large Stage-2 negative adjustments (T-Mobile, Petco, Tropicana) are now
      correctly reflected in the edge — ensuring we don't over-bet pitcher-friendly parks
  (b) Large Stage-2 positive adjustments (Coors Field, Fenway wind-out) will now
      correctly boost edge in hitter-friendly parks — potentially unlocking good bets
      that were borderline under the old (S1+S3 only) calculation
  (c) The reported FV and edge numbers are now accurate

For COL@SD 8.5: the corrected true edge was 0.176 (vs reported 0.215).
If a similar bet appeared with edge=0.135 reported but true edge would be 0.096 at a
pitcher-friendly park, the old code would BET and the fixed code would correctly SKIP.

FIX STATUS: Implemented in paper_trader.py line 611 before TR7.

simultaneously, we stake $200-$300 on a single game's outcome. In TR6 this worked out
because WSH@MIL ended 14 total (far over any line), but in a loss scenario we would
take 2-3× the loss on one correlated outcome.

the dedup logic correctly handles this per-line. But it's worth noting as a risk
concentration pattern. The current system allows unlimited same-game bets across
different lines, and the same scoring event can trigger multiple lines at once.

(WSH@MIL added $117 from bets #6 and #7 after #3 was already in). Consider adding
a max_concurrent_bets_per_game parameter only if we see correlated multi-line losses.
