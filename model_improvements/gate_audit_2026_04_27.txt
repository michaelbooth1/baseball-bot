MLB Totals Over Gate Audit
==========================
Date: 2026-04-27
Scope: live candidate/outcome logs from 2026-04-23 through 2026-04-26,
plus one historical 2025 backtest cross-check.

Question
--------
Each gate should save more loss value than it gives up in blocked win value.

Dollar method
-------------
Values are normalized to $1 stake:

  If a blocked candidate would lose:
    loss_value_blocked = +1.00

  If a blocked candidate would win at decision ask A:
    win_value_blocked = (1 / A) - 1

  net = loss_value_blocked - win_value_blocked

Positive net means the gate is helping on the labeled sample.
Negative net means the gate is over-blocking in that sample.

Primary unit
------------
The primary table deduplicates by material state:

  session_date, game_pk, line, decision_reason, inning, inning_state, outs,
  current_total, score, runners_on, ask bucket, edge/FV buckets, relax metadata.

This avoids tick spam while preserving materially different game states.

  Negative across every major subgroup:
    ask < 0.65:       n=6,  W-L=5-1,  net=-2.30
    ask 0.65-0.75:    n=6,  W-L=6-0,  net=-2.70
    ask 0.75-0.85:    n=10, W-L=10-0, net=-2.68
    ask >= 0.85:      n=10, W-L=10-0, net=-1.17
    lead 4-5:         n=16, W-L=15-1, net=-4.77
    lead >= 6:        n=16, W-L=16-0, net=-4.07
    runs_needed <=0.5 n=21, W-L=21-0, net=-6.15

  Current evidence says this gate is over-protective. It is blocking many
  games where the total is already one run from going over and the market ask
  is often high. Because it fires before FV inference, we cannot see whether
  the model/min-edge gates would have rejected those anyway.

gate_inning6_runs_needed:
  Strong positive. It remains the best-proven structural gate in the live data.
  Shadow would-pass rows: n=24, W-L=10-14, net=+10.08.

gate_inning5_runs_needed:
  Positive overall, but context-sensitive:
    rn <= 2.5: n=12, W-L=4-8,  net=+7.00
    rn <= 3.5: n=21, W-L=14-7, net=+0.91
  Keep it, but continue ask/runs-needed stratification.

gate_fv_saturation:
  Positive overall, but not uniformly:
    ask < 0.65:  n=9,  W-L=6-3,  net=-0.88
    ask >=0.85:  n=35, W-L=33-2, net=-0.21
    lead <2:     n=9,  W-L=3-6,  net=+5.74

  This suggests the gate is useful when the game is near the line in a close
  context, but may be too blunt in high-ask market-confirmed states.

gate_runs_needed_max:
  Negative as a first blocker, but not a clean relaxation candidate. Most rows
  would hit gate_close_game_runs_needed or gate_inning5_runs_needed next. This
  needs sequential ablation or explicit shadow at 4.5 before changing.

gate_min_current_total:
  Slightly negative by material rows and near neutral by market-line dedup.
  Existing conditional relax framework is appropriate. Do not globally lower
  min_current_total yet; keep testing inning=4/current_total=3/ask>=0.60.

Recommendations
---------------

1) Highest ROI/risk patch: rework gate_blowout.
   Current live labeled sample is strongly negative. Recommended design:
     - Move blowout evaluation after FV inference, or at minimum compute/log FV
       before blocking.
     - Promote the existing blowout conditional relax from shadow to A/B or
       enforce for a limited test:
         allow when inning <= 7, ask >= 0.74, runs_needed <= 2.5.
     - Add an explicit "runs_needed <= 0.5" subtest; current data is 21W/0L.

2) Keep gate_inning6_runs_needed unchanged.
   It is the strongest positive gate in both primary and shadow views.

3) Keep gate_inning5_runs_needed, but split future reports by rn=2.5 vs rn=3.5.
   The 2.5 bucket is strongly protective; the 3.5 bucket is only mildly positive.

4) Keep gate_fv_ask_gap unchanged.
   Small sample, but consistently positive and aligned with phantom-run theory.

5) Keep gate_min_edge unchanged.
   Positive in primary, market-line dedup, and shadow relaxed rows.

6) Do not globally relax gate_runs_needed_max yet.
   Its first-blocker result is negative, but downstream gates catch most rows.
   Add a shadow threshold at 4.5 or run a sequential ablation before changing it.

7) Do not globally lower min_current_total yet.
   Existing conditional relax framework is correct. Continue testing inning=4,
   current_total=3, ask>=0.60 contexts.

8) Add candidate logging for Gates 1-5.
   Current live data cannot dollar-audit inning floor, inactive state, min ask,
   spread, or jump confirmation at the same quality level as Gates 6+.
