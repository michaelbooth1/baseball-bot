================================================================================
NEW HIGH-PRIORITY FINDINGS (BUGS / LOGIC GAPS)
================================================================================

P0-A) Limit-price edge integrity is not guaranteed
--------------------------------------------------
Where:
- scripts/trading/real_trader.py (_compute_limit_price)

Issue:
- Logic caps limit to edge_cap and ask-0.01, then floors to bid+0.01.
- That final floor can push limit ABOVE edge_cap, violating minimum-edge intent.

Impact:
- You can post orders with weaker-than-required edge (or worst-case negative EV in edge cases).

Fix:
- After floor/cap math, enforce a final invariant check:
  - if (fair_value - limit_price) < min_edge: skip order.
- Also enforce explicit non-crossing:
  - if limit_price >= ask and not intentional taker-mode: skip or reroute.


P0-B) Kelly sizing can force a minimum bet even when Kelly says "no bet"
------------------------------------------------------------------------
Where:
- scripts/trading/real_trader.py (_compute_stake)

Issue:
- kelly_full is clamped at >=0, but stake then applies max(min_order_size, stake_raw).
- If kelly_full == 0, stake_raw == 0, but function still returns min_order_size.

Impact:
- Strategy can place mandatory small bets when edge-at-limit is zero/negative.

Fix:
- If stake_mode == kelly and kelly_full <= 0: return 0 and skip.
- Keep min_order_size only for genuinely positive-kelly stakes.


P0-C) Partial fill handling is incomplete
-----------------------------------------
Where:
- real_trader + paper_trader settlement/accounting flow

Issue:
- Lifecycle mostly treats bets as binary filled vs not-filled.
- fill_size exists but realized PnL and budget accounting do not fully use proportional exposure.

Impact:
- Realized PnL, risk, and budget can be biased when orders partially match.

Fix:
- Track matched_notional and unmatched_notional separately.
- Settle realized PnL on matched size only; unmatched portion is missed signal.
- Budget should count matched deployed + unmatched reserved.


P1-A) Resume path does not fully restore live open orders into _open_orders
----------------------------------------------------------------------------
Where:
- scripts/trading/real_trader.py (_load_existing_session)

Issue:
- Resume marks line state bet_open, but does not rebuild full polling map
  (_open_orders[order_id] = bet) for live/pending orders.

Impact:
- Crash/restart edge case can leave true live orders unmanaged.

Fix:
- On resume, for unsettled live/pending bets with order_id, repopulate _open_orders.
- Then perform immediate sync poll.


P1-B) FV-decay cancellation appears too reactive in first seconds
-----------------------------------------------------------------
Evidence:
- 2026-04-20 session includes an fv_decay cancel very shortly after placement that later
  would have won.

Issue:
- Single fast FV drop can trigger cancellation before signal stabilizes.

Fix:
- Add min age before fv_decay (example: 20-30s).
- Require 2 consecutive decay checks before cancel.
- Optionally combine with ask trend confirmation (falling ask + FV drop together).

1) Inning-state dead-zone filters are directionally right, but continue to prefer
   targeted context filters over blanket inning bans.

2) Execution alpha now matters as much as signal alpha.
- With signal direction strong but realized ROI weak, each missed fill is expensive.
- Treat order placement as an optimization problem:
  maximize EV = P(fill)*EV_if_filled + (1-P(fill))*EV_if_missed.

- If you tune spread_factor on periods with unusually high/low volatility,
  you can overfit microstructure regime.
- Use rolling window evaluation and holdout sessions.
